# プラグインを会話から挿入する（v0.10）

Maxデバイスとは別に、Liveのブラウザー操作を担当するRemote Scriptを一度登録します。

## 簡単セットアップ

READMEの npm run setup を実行すれば、以下のファイル配置とAI側設定をまとめて行えます。Liveのコントロールサーフェス選択だけは初回に手動で行います。

## 個別に導入する場合

1. `npm run build`でdistを生成します。
2. 次のコマンドのパスを、Liveの環境設定で指定しているユーザーライブラリの絶対パスに置き換えて実行します。

```sh
node dist/install-browser.cjs "C:/path/to/Ableton/User Library"
```

3. Liveを再起動します。
4. 環境設定 → Link/Tempo/MIDI → 空いているコントロールサーフェス欄を`LiveBridgeBrowser`にします。
5. **入力：None、出力：None**。KeyLabなど既存のコントローラー設定は維持します。
6. AI側のMCPを再接続し、48ツールがあることを確認します。`live_browser_status`、`live_search_plugins`（query: L2）で読み取りを試します。

登録はLive全体の設定なので、プロジェクトごとに設定し直す必要はありません。Noneに戻すと検索・挿入は停止しますが、挿したプラグインは残ります。Maxデバイス経由のMIDI・音量・テンポ操作は別経路です。

## 依頼例

「KickとSnの末尾にWaves L2 Stereoを挿して。既にあればスキップして」

AIは状態取得→検索→対象照合→1本ずつ挿入→結果確認の順で処理します。`targetId`はRemote Script用で、Max側の`trackId`とは別物です。

音声出力のある通常・グループ・リターン・マスタートラックが対象です。再生・録音中、フリーズ中、ホットスワップ中は拒否します。製品名の制限なしで、検索結果のitemIdをlive_insert_pluginに渡して最上位チェーン末尾へ挿入します。TR5 Space Delayなどにも対応する経路です。空のMIDIトラックへの音源挿入とRack内部は対象外です。

タイムアウト後は挿入済みの可能性があるため状態を読み直します。同じプラグインを複数個挿すことも可能です。重複を避けたい場合は、挿入前に一覧を確認してスキップしてください。複数トラックを一括で戻す機能、Set自動保存はありません。

## 更新

リポジトリ更新後に再ビルドし、同じユーザーライブラリへ再インストールしてLiveを再起動します。トークンを作り直した場合はMaxデバイスとRemote Scriptの両方を更新してください。

更新後はlive_browser_statusのversionが0.2.0、capabilities.pluginInsertionがany_searched_pluginであることを確認します。旧Remote Scriptが動いている場合はMCPが挿入を止め、更新案内を返します。新しいプラグイン名の一般化は模擬環境で検証済み、Live実機での追加検証は未実施です。
